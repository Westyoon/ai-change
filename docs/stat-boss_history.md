## 제작 틀 (3단계)

지난 미니게임 때처럼 크게 3단계로 나눔. 순서는 그대로(로직 → 흐름 → 렌더링) — 판정 수치가 안 잡힌 상태에서 화면부터 만들면 나중에 다시 뜯어야 하는 부분이 많았어서.

### 1단계 — 판정 로직 · 데이터 구조

화면 없이 순수 로직/데이터만. 콘솔이나 유닛 테스트로 검증 가능한 상태를 목표로 함.

- [x] 그리드(타일) 기반으로 결정 변경
- [x] 격자 정의: 바닥을 7열×5행 타일로 분할. 캐릭터는 자유 이동, 판정 시에만 좌표→타일 변환
- [x] 판정 shape 프리미티브: `cell` 단일 칸 / `row`·`column` 한 줄 / `diagonal` 대각선 / `block` 사각 범위 / `inverse` 지정 칸 제외
- [x] 패턴 데이터 구조: 5종 패턴(①단일 저격 ②광역 확산 ③좌우 스윕 ④다중 락온 ⑤연속 콤보)을 `getSteps(ctx)` 형태로 정의
- [x] 패턴별 shape 매핑: ①`cell` / ②`inverse` / ③`column` 순차 이동 / ④`cell`×2~3 고정 / ⑤`diagonal`→`block` 2step
- [x] 스탯 공식: 데미지 = 기본값×(1+공격력×계수) / 피격 = 보스공격력−방어력(최소1) / 최대HP = 체력 스탯 기반
- [x] 회피 판정: 예고 종료 시점 위치가 위험 칸 밖이면 성공
- [x] 경직·반격 판정: 경직 시간(예: 1.2초) 내에만 반격 유효
- [x] 난이도 스케일링: 0~15초(①만,1.5초) / 15~40초(①②③,1.2초) / 40초~(전체,0.8초→하한0.5초)
- [x] 인원별 보스 체력 배율: 1인×1.0 ~ 5인×1.8
- [x] ③ 좌우 스윕 step별 예고 시간 — 첫 step은 기본값, 이후는 1/3(최소300ms)로 가정 (임시)
- [x] 재도전 규칙: 실패해도 스탯 비감소 — encounter.js가 외부 스탯을 직접 못 건드리는 구조로 보장. 단 시간초과 기준값은 v3에서 아직 못 찾음(임시: 무제한)

### 2단계 — 웨이브 진행 · 게임 상태 흐름

- [x] 예고→회피→경직→반격→다음 패턴 루프 (`encounter.js`)
- [x] 경과 시간별 패턴 랜덤 스케줄러
- [x] 공통 게임 상태(`READY→RUNNING↔PAUSED→RESOLVING→COMPLETED`) 재사용 (`state.js`)
- [x] pause 처리: RUNNING 아닐 때 tick 무시 → 타이머 자동 정지
- [x] Battle lifecycle 계약: `init/start/pause/resume/restart/destroy` + `onComplete`
- [x] 결과 candidate 구성: `status/score/failureReason/metrics/reward`

### 3단계 — 화면 렌더링 · 입력 연결

- [x] 격자 바닥 렌더링 + 예고/공격/경직 연출, 위험 타일 하이라이트
- [x] 보스 HP바, 플레이어 HUD, 남은 시간 표시 (단, "남은 시간"이 아니라 "경과 시간"임 — 논의 사항 ①과 연동)
- [x] 공용 캐릭터 시스템 이동·공격 API 연동
- [x] PC/모바일 입력 연결 (터치 버튼 44×44px 이상) — 조이스틱 100~124px, 공격 버튼 78~94px
- [ ] 처치 연출 → 결과 화면 전환 — 처치 연출 자체가 아직 없음(승패 갈리면 그냥 멈춤). "결과 화면"은 공용 result-overlay.js 몫
- [ ] 결과 화면 UI: 클리어 시간·피해·반격 수, 재도전/허브 버튼 — 데이터(candidate.metrics)는 준비 완료, 화면은 공용 result-overlay.js 몫(라벨 등록 필요)
