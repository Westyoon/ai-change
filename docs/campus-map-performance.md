# 캠퍼스 맵 전환 준비와 재사용

2026-10-26 문을 누른 뒤 이미지와 충돌 데이터를 매번 다시 준비하던 비용을 줄였다. 지도·이미지 원본, 배치, 캐릭터 비율과 화질은 바꾸지 않는다.

- 로딩 화면이 끝나면 유휴 시간에 ECC부터 다른 맵의 이미지를 미리 읽고 디코딩한다. 현재 맵 진입 뒤에도 준비를 이어간다. 준비 중인 요청도 공유하며, 완료된 이미지 객체와 JSON은 페이지 안에서 보관한다. 실패한 항목은 캐시에서 제거해 다음 입장 때 재시도한다.
- 지도 관리자 하나를 재사용하고 맵·사전/사후 모드별 충돌 격자를 보관한다. 격자 생성은 각 도형의 범위만 순회하되, 기존과 동일하게 셀 중심에서 길의 합집합에서 장애물을 뺀다.
- 라우터의 선택적 `prepare` 단계에서 다음 맵의 분리된 레이어를 만든다. 이 단계가 끝나기 전에는 기존 화면과 생명주기를 유지한다. 다른 화면으로 이동하면 준비 대기만 취소하고 공유 에셋 로딩은 재사용한다.
- 사후맵의 기존 세션 확인도 준비 단계에서 수행하며 직접 mount하는 경우의 세션 확인은 유지한다. 준비 완료 뒤 기존 맵을 정리하고 다음 맵을 붙인다. 조작·NPC 진행·실시간 위치는 캐시하지 않는다.

처음 필요한 파일을 내려받는 시간은 연결 속도에 영향을 받는다. 미리 준비가 끝난 맵은 이미지 다운로드·디코딩과 충돌 재계산 없이 전환한다. 새 배포의 파일과 설정은 페이지를 새로고침하면 다시 읽는다.

## 검증

전체 검사 537개, 소스 HTTP 80개, 빌드 HTTP 93개와 백엔드 TypeScript 검사를 통과했다. 추가 검사는 공유 요청·이미지 재사용, 한 소비자의 취소가 다른 소비자에게 미치는 영향, 오류 후 재시도, 지도 관리자와 모드별 격자 재사용, 준비 중 기존 화면 유지·화면 종료·새 이동 요청에 의한 취소, 겹침/소수 좌표를 포함한 셀 판정 동일성을 확인한다.

변경 전 네 지도 × 두 모드의 전체 격자를 SHA-256으로 저장한 뒤 변경 후와 대조해 여덟 결과 모두 일치했다. 기존 도형 기반 이동·충돌 검사도 통과했다.

로컬 브라우저 1280px/터치 390px에서 실제 Battle 장면 래퍼와 라우터로 이미지 응답을 지연시켜 야외 화면이 남는지 확인했다. 준비 취소 후 재진입해도 공유 요청을 이어 쓰며 전환 중 빈 프레임은 없었다. 준비된 맵의 전환·다음 프레임까지 측정한 값은 약 0.02~0.21초였다. 학생 대화·색상·목표 초기화와 건물 버튼/Space 출입 검사도 통과했다.

재현용 상세 계측과 이전 운영 측정값은 작업 출력의 `indoor-transition-before.json`, `indoor-transition-local-after.json`에 보관했다. 네트워크 상태와 선행 로딩 완료 여부가 달라 첫 입장 수치와 준비 완료 후 수치를 직접 같은 조건으로 간주하지 않는다.
