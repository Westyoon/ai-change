# ai-change 실행 및 조작 방법

## 1. 현재 구현 상태

이 문서는 `contentVersion=1` 통합 개발본 기준입니다. 공통 화면, 학과 데이터, 맵·대화 연결과 기능 브랜치에서 합쳐진 미니게임을 확인할 수 있습니다. DS·CS·CSE·AI·AIDS 5종은 모두 MVP이며 최종 밸런스·점수·기록 정책은 아직 확정되지 않았습니다.

현재 Story는 `1024×640` 논리 월드를 캐릭터로 직접 돌아다니는 방식입니다. `Story`에 처음 진입하면 공통 인트로가 대사창으로 나오고, 이후 학과 수호자에게 가까이 가서 상호작용하면 해당 학과 이야기와 게임 방법을 거쳐 미니게임을 시작합니다. 처음 CLEAR하면 학과별 마무리 이야기와 수호알 획득 연출이 이어지며, 얻은 수호알과 설명은 맵 우측 상단 인벤토리에서 확인합니다. 서로 다른 수호알 5개를 모두 모으면 맵 위쪽의 최종전 `word-breaker` 포털이 열립니다. 사후 이동 월드는 Battle 메뉴에서 별도로 열리며, X알이 출현하지 않는 중심 광장에서 시작합니다. 광장 오른쪽 끝은 랜덤 미니게임 필드의 왼쪽 안전 위치로 이어지고, 필드 왼쪽 끝으로 가면 광장으로 돌아옵니다. 광장 위쪽의 세 문은 각각 `data-sphinx`, `stat-boss`, `control-boss`로 연결됩니다. `xr-egg-trials`는 필드를 실제로 걷는 동안에만 랜덤으로 출현합니다. 모든 구역 전환은 창 새로고침 없이 이루어집니다. 교체된 전역 prototype과 개발 harness는 production `dist/`에 포함하지 않습니다.

### 2026-09-28 Story 월드 흐름

- 공통 인트로는 계정·브라우저별 최초 한 번만 표시하며, 이후에는 인벤토리의 `우리의 기억`에서 다시 봅니다.
- 학과 수호자에게 가까이 가면 느낌표와 상호작용 안내가 나타납니다. PC는 `Space`·`Enter`·`E`, 모바일은 화면의 `대화` 버튼을 사용합니다.
- 처음 만난 수호자는 학과별 도입 이야기를 먼저 보여 주고, 이미 본 경우에는 게임 방법 화면으로 바로 이어집니다.
- 미니게임을 처음 CLEAR하면 완료 기록을 먼저 저장한 뒤 학과별 마무리 이야기와 수호알 획득 연출을 보여 줍니다. 같은 게임을 다시 CLEAR해도 이 연출을 강제로 반복하지 않습니다.
- 인벤토리의 `우리의 기억`에서는 공통 인트로와 각 학과의 도입·마무리 이야기를 다시 볼 수 있으며, 아직 보지 않은 기억은 선택할 수 없습니다.
- 모바일 세로 화면은 월드를 찌그러뜨리지 않고 플레이어 중심 카메라로 보여 주며, 노트북 화면은 같은 논리 월드를 최대한 한 화면에 맞춰 표시합니다.

학과 표기는 다음 코드를 공통으로 사용합니다.

| 코드 | 학과·전공 | 짧은 이름 |
| --- | --- | --- |
| `AI` | 인공지능학부 | 인공지능 |
| `DS` | 데이터사이언스전공 | 데이터사이언스 |
| `CSE` | 컴퓨터공학과 | 컴공 |
| `CS` | 사이버보안학과 | 사이버보안 |
| `AIDS` | 인공지능데이터사이언스학부 | 인데부 |

## 2. 로컬 실행

게스트 흐름은 별도 backend 설치가 필요 없는 정적 웹게임으로 실행할 수 있습니다. Node.js 22 이상과 저장소에 포함된 개발 서버를 사용합니다. `fetch()`로 JSON을 읽으므로 `index.html`을 파일 탐색기에서 직접 열지 말고 반드시 로컬 HTTP 서버를 사용합니다. Google 로그인·D1을 로컬에서 확인할 때는 README의 `cf:full:dev` 절차를 사용합니다.

PowerShell에서 프로젝트 루트로 이동한 뒤 다음 명령을 실행합니다.

```powershell
cd C:\Users\yoons\project\ewha-ai\ai-change
npm run dev
```

기본 주소는 다음과 같습니다.

```text
http://127.0.0.1:4173/
```

운영 기능 확인은 canonical 통합 Worker인 `https://ai-change.ai-change-backend.workers.dev`에서 수행합니다. 기존 `ai-change.pages.dev` 프로젝트는 폐기했으므로 사용하지 않습니다. Google 로그인 테스트 전에는 계정 ID·이메일·표시 이름이 D1에 저장되고 표시 이름과 게임 기록이 공개 랭킹에 노출된다는 점을 참가자에게 먼저 고지합니다.

환경 변수 `PORT`가 이미 설정된 경우에는 개발 서버가 출력한 주소를 사용합니다. 서버는 실행 중인 PowerShell에서 `Ctrl+C`를 눌러 종료합니다.

구조와 데이터까지 한 번에 검증하려면 다음 명령을 실행합니다.

```powershell
npm run check
```

## 4. 기본 진행

```text
로딩
  → 메인 메뉴
  → Story
  → 공통 인트로 대사(최초 1회)
  → 캐릭터 이동형 Story 맵
  → 학과 수호자 근처에서 상호작용
  → 해당 학과 도입 이야기(최초 1회)
  → 게임 방법 확인
  → 게임 시작 버튼
  → 미니게임 플레이
  → CLEAR 결과
  → 학과 마무리 이야기(최초 1회)
  → 수호알 획득
  → 맵 복귀
```

Battle 메뉴는 `features.battleContent=true`와 `data/battles.json`의 published 콘텐츠 5종을 사용합니다. 해금 판정은 로컬 완료 기록과 로그인 session의 `completedGameIds`를 합쳐 서로 다른 필수 5종을 모두 완료했는지 확인하며, 그전에는 메뉴 버튼 자체가 비활성화됩니다. 현재 운영 점검 기간에는 `features.guestBattleTesting=true`라 로그인 실패 상태에서도 Battle 월드와 랜덤 게임을 열 수 있습니다. 게스트가 보스 문에 들어가면 로컬 테스트 대기실에서 방 이름·정원을 정해 방을 만든 뒤 방장이 `전투 시작`을 눌러야 하며 자동 시작하지 않습니다. 이 방은 다른 사용자와 동기화되지 않습니다. 로그인 사용자는 기존처럼 서버의 공개 방을 만들거나 참가하고, 진행 중 전투 재접속 시 `이어하기 / 전투 나가기`를 선택합니다. 점검 종료 후 플래그를 `false`로 바꾸면 로그인 필수 규칙으로 복귀합니다.

## 5. 공통 조작

| 상황 | PC | 모바일 |
| --- | --- | --- |
| Story 맵 이동 | 방향키 또는 `WASD` | 화면 가상 조이스틱 |
| Story NPC·최종전 상호작용 | 대상 가까이에서 `Space`·`Enter`·`E` | 대상 가까이에서 `대화`·`입장` 버튼 |
| Story 인벤토리·우리의 기억 | 우측 상단 수호알 버튼 | 우측 상단 수호알 버튼 |
| 메뉴·버튼 선택 | 마우스 클릭, 키보드 포커스 후 `Enter` | 버튼 터치 |
| `stat-boss` 이동 | 방향키 또는 `W`·`A`·`S`·`D` | 왼쪽 조이스틱 |
| `stat-boss` 경직 중 반격 | `Space` | 오른쪽 공격 버튼 |
| `data-sphinx` O/X 선택 | 방향키 또는 `W`·`A`·`S`·`D`로 영역 이동 | 가상 조이스틱으로 영역 이동 |
| `control-boss` 이동·공격 | 방향키 또는 `W`·`A`·`S`·`D`, `Space` | 가상 조이스틱, 공격 버튼 |
| `xr-egg-trials` | 선택 버튼 또는 `Tab`·`Enter`; 연타는 `Space`도 가능 | 화면의 카드·선택·연타 버튼 터치 |
| `word-breaker` | 방향키 또는 `W`·`A`·`S`·`D`로 이동; 기본 탄 자동 발사 | 가상 조이스틱으로 이동; 기본 탄 자동 발사 |
| 일시정지 | `Escape` 또는 `P` | 일시정지 버튼 터치 |

설정, 일시정지 또는 결과 화면이 열려 있을 때는 뒤쪽 맵·게임 입력이 차단됩니다.

`word-breaker`는 Battle 메뉴의 사후 전투가 아니라 Story를 마무리하는 게임이며, 로그인 여부와 계정 전투 스탯을 사용하지 않습니다. 일반 부정 문장은 사각형 카드가 아니라 자간을 논리 좌표 기준 최대 `2.4px` 넓힌 개별 grapheme으로 내려오며, 문장은 좌우로 천천히 흔들리고 글자들은 작은 상하 물결을 만듭니다. 이 움직임은 CSS 장식이 아니라 실제 글자 좌표에 적용되어 화면에 보이는 글자만 같은 위치에서 플레이어·탄과 충돌합니다. 일반 문장의 비강조 글자는 학과와 관계없이 밝은 미색 `#fff8f2`로 통일하고, 공격 가능한 글자만 밝은 노란색 `#fff45c`로 구분합니다. 홀수 번째 문장은 원문의 의미상 핵심을, 짝수 번째 문장은 같은 글자 수만큼 왼쪽 부분을 공격 표적으로 삼아 좌우 모두 실제 플레이에 등장합니다. 글자 위 특수 기호나 밑줄은 표시하지 않습니다. 자동 탄은 이동 방향과 무관하게 플레이어 앞쪽인 화면 위 방향으로만 곧게 발사되며, 노란 글자를 합계 7회 맞히면 문장이 정화됩니다. 탄 속도와 발사 간격은 각각 `320px/s`, `260ms`이고, 문장은 `44px/s`로 내려와 `1850ms`마다 생성되므로 읽고 이동해 조준할 시간이 늘어났습니다.

각 13.5초 일반 라운드 뒤에는 내부적으로 2.4초의 `OMEN`과 4.2초 안전 상승 구간을 거칩니다. 이 단계는 HUD에서 별도 페이즈로 드러나지 않지만, 붕괴 공격이 고정되는 순간 화면이 한 번 흔들리고 이아이가 현재 학과의 부정 문장 하나를 다시 내뱉습니다. 일반 문장과 탄은 전역 최소 `600ms` 및 패턴별 추가 지연을 거쳐 첫 오류 글자가 실제 활성화될 때까지 계속 생성·이동·충돌하고, 같은 시뮬레이션 단계에서 붕괴 공격으로 교대합니다. DS는 상하좌우 네 방향의 데이터 축 공격, CS는 한 곳의 탈출구를 둔 원형 방화벽, CSE는 재귀 분기, AI는 예측 후보 수렴, AIDS는 데이터·모델 피드백 순환을 사용하며 seed에 따라 진입면·레인·회전 방향·안전구역이 달라집니다. 일반 오류 글자는 2회, 폭주 오류 글자는 3회 맞히면 부술 수 있습니다. 고밀도 폭주의 첫 두 웨이브도 회피하거나 부술 수 있고, 그 뒤 `unavoidable` 웨이브가 실제로 닿을 때만 전체 5칸 생명 중 정확히 한 칸을 잃고 해당 학과 수호알이 각성합니다. 첫 네 번은 `STAGGERED` 뒤 다음 라운드로 이어지고, 다섯 번째에만 `KNOCKED_OUT`이 됩니다. 이어서 다섯 수호알이 동시에 나타나 `REVIVED`에서 생명을 `5/5`로 한 번에 회복하며 공명 응원을 보여 줍니다. 실패나 게임 오버는 없고, 마지막 문장은 3.2초 동안 자동 정화된 뒤 `CLEAR`가 됩니다.

## 6. 미니게임별 조작

설정 파일의 `implementationStatus`는 실제 통합 수준에 따라 `MVP`, `PROTOTYPE`, `SCAFFOLD`로 구분합니다. 아래 조작 계약은 유지하되 `data/drafts/`의 미확정 규칙과 밸런스는 후속 결정에 따라 바뀔 수 있습니다.

| 코드 | 미니게임 | 상태 | PC | 모바일 |
| --- | --- | --- | --- | --- |
| `DS` | 숫자 야구 | MVP | 숫자 키·화면 키패드 입력, `Backspace` 삭제, `Enter` 제출 | 화면 키패드, 지우기·제출 버튼 |
| `CS` | CLICK to PURIFY · 22 wave | MVP | 설명창의 `✕` → `START` 후 `Space` 또는 `CLICK` 버튼으로 정화 | 설명창의 `✕` → `START` 후 `CLICK` 버튼 터치 |
| `CSE` | Code Heart: Unlock! | MVP | 마우스로 재료·초기화·제출 선택 | 해당 버튼 터치 |
| `AI` | AI Ball Classification · 목표 5/방해 25 | MVP | `게임 시작`과 3초 확인 후 `Space` 또는 `OPEN·CLOSE` 버튼으로 분류통 뚜껑 전환 | `게임 시작`과 3초 확인 후 `OPEN·CLOSE` 버튼 터치 |
| `AIDS` | 인지알·데사알 분류 게임 | MVP | 방향키 또는 `A`·`D`로 발판 조작 | 왼쪽·오른쪽 버튼 터치 |

AI는 `480×640`, AIDS는 `390×740` MVP 세로 프레임 전체를 모바일에서 비례 축소하고 가용 높이가 충분한 큰 화면에서 각각 최대 약 `1.33배`·`1.35배`까지 비례 확대합니다. 두 게임은 데스크톱에서도 HUD·Canvas 또는 필드·조작부를 재배치하지 않아 원본 위치와 종횡비를 유지합니다. CSE는 모바일에서 `440×920` 원본 세로 프레임을 유지하고 충분히 큰 데스크톱에서는 손님·작업대·재료 카드를 2열로 재배치하며, DS도 넓은 화면에서 입력·기록 영역을 2열로 재배치합니다. CS의 `480×480` Canvas와 `300px` 조작 패널은 같은 비율로 최대 `720px`·`450px`까지 커지고, 공간이 부족하면 원래 prototype처럼 위아래로 줄바꿈됩니다. Word Breaker는 `450×800` 논리 영역을 유지해 모바일 세로 화면에 비례 축소합니다. 5칸 생명바는 전투 영역 최상단에 고정되며 생명이 줄수록 균열·정적 노이즈·색 분리 효과가 5단계로 강해집니다. HUD 통계값과 상태 문구는 고정된 높이 안에서 말줄임 처리하므로 같은 viewport에서는 페이즈가 바뀌어도 전투 필드 크기가 변하지 않습니다. 넓힌 자간과 글자별 물결, 상단 생명바, 마지막 다섯 수호알 부활 연출은 모두 같은 논리 영역 안에서 함께 비례 축소되며 `prefers-reduced-motion`에서는 정적 이동 애니메이션을 끕니다.

## 7. 로컬 데이터

- 현재 저장 namespace는 `ai-change:production`이며 save schema key는 `ai-change:production:save:v1`입니다.
- 현재 key가 비어 있고 같은 origin에 기존 `ai-change:development:save:v1` 기록이 있으면 최초 로드에서 production key로 한 번 복사하며, legacy 기록은 삭제하지 않습니다.
- 브라우저 저장소를 삭제하면 로컬 진행과 설정이 초기화될 수 있습니다.
- 계정, 개인정보, 서버 점수는 브라우저 저장소에 저장하지 않고 로그인한 운영 Worker/D1에서 관리합니다.
- 로그인 session이 반환한 `completedGameIds`는 로컬 완료 기록과 합쳐 배틀 해금에 사용합니다.

## 8. 문제 해결

| 증상 | 확인 사항 |
| --- | --- |
| 빈 화면 또는 JSON 요청 오류 | `file://`이 아닌 `npm run dev`가 출력한 HTTP 주소로 접속했는지 확인 |
| 이미지·JSON 404 | 프로젝트 루트에서 서버를 실행했는지 확인 |
| 콘텐츠 버전 불일치 | 강력 새로고침 후 HTML·app config·manifest가 모두 version 1인지 확인 |
| 키 입력이 동작하지 않음 | 대화·설정·결과 modal을 먼저 닫고 게임 영역에 focus |
| 모바일 버튼이 보이지 않음 | 브라우저 기기 모드 또는 실제 터치 기기에서 다시 확인 |
| Battle 카드가 `LOCKED`로 표시됨 | 로컬 기록과 로그인 계정 기록을 합쳐 서로 다른 필수 미니게임 5종을 모두 완료했는지 확인 |
| 예전 Pages 주소가 열리지 않음 | 해당 프로젝트는 폐기했으므로 canonical 통합 Worker 주소로 다시 접속 |
