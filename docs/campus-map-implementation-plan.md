# 공통 캠퍼스 맵 구현 계획

작성일: 2026년 10월 16일

## 구현 방향

첨부 캠퍼스 그림을 사전·사후게임의 공통 배경으로 사용한다. 그림 위에 캐릭터만 올리는 방식에서 끝내지 않고, 포장길·광장·계단에 이동 가능 영역을 지정한다. 나무·건물·화단·온실·부스 내부에는 들어갈 수 없게 한다.

기존 이동·연속 충돌 처리(`js/map/collision.js`)와 사후게임 캐릭터 시스템은 활용할 수 있다. 현재 충돌기는 사각형 목록을 받으므로, 이 그림의 복잡한 길을 표현하려면 이동 가능 영역을 위한 판정과 맵 좌표·카메라 연결을 추가해야 한다.

이번 단계는 계획 작성이며, 맵 교체나 배포는 하지 않았다.

## 1. 맵을 웹 화면에 표시하는 방법

- 배경 원본 픽셀 크기를 월드 좌표로 삼는다. 화면이 바뀌어도 길·캐릭터·충돌 지도·상호작용 지점은 같은 좌표계를 사용한다.
- 배경을 가로·세로 각각 늘려 왜곡하거나 `cover`로 잘라내지 않는다.
- PC에서는 창 크기에 따라 맵을 보여주되, 캐릭터와 길이 너무 작아지는 수준으로 전체를 축소하지 않는다.
- 모바일에서는 캐릭터 주변을 보여주는 추적 카메라를 사용한다. 전체 지도를 억지로 한 화면에 넣지 않는다.
- 카메라는 맵 가장자리에서 멈추고, 화면 크기 변경·회전 시 캐릭터 위치와 판정을 보존한다.
- PC 방향키/WASD, 모바일 조이스틱을 유지한다. 클릭 이동·경로 탐색은 첫 버전 필수 범위에 넣지 않는다.

## 2. 길과 장애물 판정

이 그림에는 좁고 굽은 길이 많으므로, **이동 가능한 길을 먼저 지정하는 방식**을 권장한다.

1. 배경 위에 포장길·광장·계단을 따라 이동 가능 영역을 그린다.
2. 편집한 영역을 충돌용 격자로 변환한다. 시작값은 원본 기준 8~16px 간격이며 좁은 길에서 조정한다.
3. 격자에서 나무·화단·건물·난간·온실·부스 영역은 기본 차단한다. 포장길 위의 벤치·화분·가로등 기둥 등도 필요한 만큼 막는다.
4. 캐릭터 전체 그림이 아니라 발밑의 작은 충돌 영역으로 이동을 검사한다. 머리카락 때문에 좁은 길을 못 지나가는 문제를 피한다.
5. 대각선 이동으로 나무 모서리를 통과하지 못하게 하고, 벽 옆에서는 자연스럽게 미끄러져 이동하게 한다.
6. 프레임이 지연될 때도 장애물을 뚫지 않도록 기존 연속 이동 검사를 새 판정에 연결한다.

오른쪽 큰 계단은 첫 버전에서 일반 보행로로 연결한다. 실제 높이·점프·중력은 추가하지 않는다. 계단과 길이 시각적으로 맞닿더라도 난간이나 단차가 있으면 막고, 실제 계단 출입구만 연결한다.

나무 색을 자동으로 골라 충돌을 정하는 방식은 쓰지 않는다. 노란 나무·녹색 부스·꽃·건물 그림자 때문에 오판정이 생긴다. 편집용으로 이동 가능 영역과 캐릭터 발 판정을 표시하는 디버그 화면을 만든다.

## 3. 이 그림에서 사용할 동선

| 위치 | 활용 제안 | 이동 처리 |
|---|---|---|
| 하단 중앙 입구 | 기본 시작·복귀 지점 | 계단으로 중앙 정원과 연결 |
| 중앙 온실 주변 | 탐색·이아이 배치 | 온실 외곽 산책로만 이동, 온실·화단 내부 차단 |
| 왼쪽 부스 광장 | 사전게임 학과 NPC 5명 | NPC는 부스 앞 보행로에 배치, 부스 내부 차단 |
| 위쪽 본관 입구 | 스토리·보스 입장 지점 후보 | 건물 앞과 계단 이동, 건물 내부는 별도 전환 |
| 왼쪽 학생회관 입구 | 보스 입장 지점 후보 | 문 앞 상호작용 구역 지정 |
| 오른쪽 계단·광장 | 세 번째 보스 입장·탐색 | 포장면과 계단만 이동, 난간·식재대 차단 |
| 중앙·외곽 산책로 | 사후 랜덤게임 조우 | 걸을 수 있는 지점에만 조우 생성 |

배치는 제안이다. 기존 학과·게임 연결, 보스 방 생성·참가, 진행 조건은 유지하고 입장 위치만 새 맵에 연결한다. 부스 6개 중 5개에 학과 NPC를 두고 나머지 1개는 안내용으로 남길 수 있다.

## 4. 사전·사후게임 연결

- 배경·이동 지도·카메라는 공통으로 사용한다.
- 사전게임은 학과 NPC, 수호알 획득 표시, 진행에 따른 입장 조건을 표시한다.
- 사후게임은 기존 보스방 로비, 랜덤게임 조우, 다른 플레이어·닉네임 표시를 새 위치에 연결한다.
- 축제 개방 후에는 이아이와 축제 장식을 표시한다. 장식 때문에 원래 길을 막지 않는다.
- 게임 종료 후 해당 입구 앞의 안전한 보행 지점으로 복귀한다. 부스·나무·건물 안에 생성되지 않게 한다.
- 기존 정규화 위치 동기화를 새 맵의 월드 좌표와 맞춘다. 맵 버전·구역을 구분하고, 서로 다른 맵 버전의 좌표가 섞이지 않도록 한다.
- 여러 계정에서 카메라 위치가 달라도 같은 월드 위치에 있는 캐릭터가 같은 곳에 보이는지 검사한다.

## 5. 필요한 에셋

| 항목 | 필요 여부 | 준비 방식 |
|---|---|---|
| 캠퍼스 배경 PNG/WebP 원본 | 필수 | 첨부 그림의 원본 파일을 프로젝트에 보관. 채팅 미리보기보다 원본 권장 |
| 길·장애물 지도 | 필수 | 코딩 작업에서 그림 위에 작성 가능. 아트팀의 별도 제작 불필요 |
| 시작점·NPC·게임 입구 좌표 | 필수 | 코드/맵 데이터로 작성 |
| 플레이어 이동 시트 | 기존 것 사용 | 현재 방향별 캐릭터 시트 재사용 |
| 나무·건물 전경 레이어 | 선택 | 캐릭터가 수관 뒤로 자연스럽게 가려져야 할 때 투명 PNG로 분리 |
| 축제 전구·깃발·부스 장식 | 선택 | 현재 픽셀 장식 재사용 또는 투명 스프라이트 추가 |
| 이아이 실제 이미지 | 추후 교체 | 기존 임시 표시를 사용하고 전달받은 뒤 교체 |

**전체 맵을 타일셋으로 다시 제작하거나 모든 나무를 잘라낼 필요는 없다.** 첫 버전은 배경 한 장과 이동 지도만으로 구현할 수 있다. 자연스러운 앞뒤 가림이 필요할 때만 전경 레이어를 추가한다. 나무 아래까지 갈 수 없도록 막는다면 전경 분리 없이도 충분하다.

## 6. 작업 순서와 검증

1. **이동 시제품**: 원본 배경·발 판정·추적 카메라·모바일 조이스틱을 연결한다. 먼저 하단 입구→중앙 정원→왼쪽 부스 구간으로 판정 방식을 검증한다.
2. **전체 동선**: 건물 앞·오른쪽 계단·외곽 길까지 이동 지도를 확장한다. 모든 게임 입구 사이의 연결성을 검사한다.
3. **기존 기능 이전**: 사전 NPC·알 진행, 사후 보스방·랜덤게임·멀티플레이를 연결한다.
4. **화면·연출**: 필요 시 전경 가림, 축제 장식, 이아이 동선을 추가한다.
5. **배포 전 확인**: PC·모바일 세로·가로 화면에서 이동, 벽 충돌, 재접속, 게임 후 복귀, 두 계정 위치 동기화, 기존 저장 진행을 검사한다.

완료 기준은 ‘그림의 길을 따라 모든 목적지에 갈 수 있고, 나무·건물·화단을 관통하지 않으며, 화면을 돌리거나 게임에 다녀와도 위치가 어긋나지 않는 것’이다.
