# 게임팀 6차 회의 반영 수정 계획안

작성일: 2026년 10월 6일
근거: 2026년 10월 5일 23:30 게임팀 6차 회의록
목적: 현재 구현을 유지하면서 플레이 오류, 전투의 전달력, 소원 게시판 운영 기능을 보완한다.

이 문서는 작업 계획이다. 아래 변경은 아직 구현·배포하지 않았다. 회의에서 결론이 난 내용과 논의만 나온 내용, 구현을 위한 제안을 구분한다.

## 1. 적용 원칙과 우선순위

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 사전게임 보상 조건·멀티플레이·모바일 검증 | 새 계정에서 플레이 없이 알을 얻지 않고, 같은 방에서 전투 상태가 일치한다. |
| 2 | 보스 판정·난이도·사망 후 관전 | 보이는 보스를 공격할 수 있고, 후반 패턴도 이동으로 회피 가능하며, 사망 후 전투를 볼 수 있다. |
| 3 | 이아이 최종전 개선 | 구출·학과 전환을 바로 알아볼 수 있고, 불가피한 쓰러짐의 이유가 스토리로 전달된다. |
| 4 | 소원 게시판 작성·삭제·관리 | 계정당 활성 소원 1개, 공개 여부 선택, 본인·관리자 삭제가 서버에서 보장된다. |
| 5 | 크리티컬·성장 조정 | 실제 피해와 표시값이 일치하고, 중복 보상 없이 성장 속도를 검증한다. |
| 6 | 추가 미니게임·홍보 연계 | 앞 작업 안정화 후 별도 범위로 진행한다. |

최근 적용한 모바일 시작 버튼, 파티원 표시, 보스 이미지 확대, 캐릭터 정렬은 수정 이력이 있다. 그러나 실제 여러 계정·기기에서의 검증을 완료한 것으로 간주하지 않는다.

## 2. 사전게임과 서버 플레이

### 사전게임 입장 즉시 수호알을 얻는 현상

- 진행 초기화 후 정상 동작했다는 제보를 근거로, 기존 저장 데이터·계정 완료 기록·입장 시 처리의 관계부터 조사한다. 원인을 저장 데이터라고 단정하지 않는다.
- 신규 계정, 기존 완료 계정, 일부 진행 계정, 게스트 진행 후 로그인한 계정을 각각 검사한다.
- 새 플레이에서 알 획득 처리는 실제 CLEAR 결과에만 연결한다. 입장·설명 닫기·기존 완료 표시를 새 클리어로 처리하지 않는다.
- 이미 얻은 알은 유지하고, 재방문에서 새 획득 연출이 반복되지 않도록 한다. 기존 진행을 일괄 초기화하는 방식으로 해결하지 않는다.
- 완료 기준: 배꽃 게임을 포함한 5개 게임 모두 입장만으로 신규 알이 지급되지 않으며, 정상 클리어 시 해당 알만 획득한다.

### 함께 플레이 검증

- 서로 다른 Google 계정으로 2인·5인 방을 만들어 캐릭터 위치, 머리색, 닉네임, 파티원 체력, 보스 체력, 전투 시작·종료를 비교한다.
- PC+모바일 조합으로 검사한다. 5인 모바일 방에서도 시작 버튼을 누를 수 있는지 포함한다.
- 방장 이탈, 일반 파티원 이탈, 전투 중 연결 끊김·재접속, 사망 후 이탈을 검사한다.
- 각 보스의 공격 예고·발동 시점이 기기마다 어긋나는지 확인한다. 공유 보스 상태와 개별 플레이어 체력을 구분해 수정한다.
- 클리어 보상은 서버가 한 번만 확정한다. 중복 이벤트·재접속·결과 재전송으로 경험치를 추가 지급하지 않는다.
- 완료 기준: 같은 방의 두 화면에서 같은 시점의 보스 HP·패턴·파티원 HP가 일치하고, 다른 방 캐릭터는 섞이지 않는다.

### 캐릭터 선택 정렬

- 네 머리색의 실제 그림 중심을 기준으로 선택 카드 안 정렬을 재확인한다.
- 캐릭터 선택창과 방 대기실에서 같은 기준을 사용한다. 프레임 전체의 빈 여백 중심과 캐릭터 몸체 중심을 혼동하지 않는다.
- 완료 기준: 머리색을 바꿔도 캐릭터가 좌우로 이동해 보이지 않고 머리·발이 잘리지 않는다.

## 3. 사후게임 보스와 성장

### 보스 이미지와 공격 판정 맞추기

- 스탯보스·컨트롤 보스의 표시 영역, 몸체 영역, 유저 공격 가능 영역을 나란히 확인한다.
- 이미지 전체 사각형을 무조건 판정으로 쓰기보다 눈에 보이는 주요 몸체에 판정을 맞춘다. 공격 모션의 잔상·빈 투명 영역은 별도로 취급한다.
- 공격 거리 안내가 있다면 실제 공격 가능 거리와 일치시킨다.
- 완료 기준: 몸체를 겨냥한 공격이 인정되고, 멀리 떨어진 투명 여백을 공격해도 맞는 현상이 없다.

### 스탯보스 후반 패턴 회피 가능성

현재 코드에는 예고 시간이 초반 1,500ms → 중반 1,200ms → 후반 800ms로 바뀌는 설정과 500ms 하한이 있다. 단순히 하한을 올리는 데 그치지 않고 실제 이동 시간을 함께 계산한다.

- 가장 가까운 안전칸까지의 거리와 캐릭터 이동 속도로 최소 회피 시간을 계산한다. 대각선 이동도 포함한다.
- 패턴 예고 시간은 필요한 이동 시간에 반응 여유를 더한 값 아래로 내려가지 않게 한다.
- 후반은 초반보다 빠르게 유지하되, 피할 수 없는 발판 배치가 생기면 배치 또는 예고 시간을 조정한다.
- 첫 조정 제안: 후반 기본 예고 1,000~1,200ms, 추가 반응 여유 250~350ms. 수치는 플레이 테스트 후 확정한다.
- 완료 기준: 위험 예고 직후 올바른 방향으로 이동하면 후반·대각선 패턴에서도 회피할 수 있다.

### 사망 후 관전

- 사망하면 해당 플레이어의 이동·공격·피격 처리는 멈추지만 보스전 화면 갱신은 계속한다.
- 살아 있는 파티원의 캐릭터, 공격 패턴, 공격 성공 표시, 보스 HP, 파티원 HP를 계속 보여준다.
- ‘관전 중’ 상태를 작게 표시하고, 전원 사망·클리어·방 이탈 시 정상 종료한다.
- 완료 기준: 사망한 계정의 화면에서도 생존자와 같은 패턴 및 보스 HP 변화를 볼 수 있다.

### 크리티컬

회의에서는 필요성만 논의했고 확률·배율은 확정하지 않았다.

- 제안값: 일반 공격에 20% 확률, 1.5배 피해. 스탯보스·컨트롤 보스에 우선 적용한다.
- 서버에서 공격별 크리티컬 여부와 실제 피해를 확정하고 파티에 전달한다. 각 클라이언트가 별도로 랜덤 계산하지 않는다.
- 피해 숫자에 크리티컬 여부를 구분해 표시한다. 기믹 고정 피해·즉사 공격에는 적용하지 않는다.
- 기존 공격 빈도 제한과 중복 공격 방지를 유지한다. 클라이언트가 임의 피해값을 보내 보스를 과도하게 깎지 못하게 한다.
- 완료 기준: 모든 화면의 크리티컬 표시·실제 보스 HP 감소가 일치한다.

### 경험치 범위 — 최신 요청과 회의록의 차이

- 현재 배포: 클리어마다 **100~200 EXP, 10 단위 랜덤**. 사용자의 직접 요청으로 적용한 값이다.
- 회의록: **100~150 EXP, 10 단위 랜덤**.
- 계획의 기본값은 최근 직접 요청인 100~200을 유지한다. 회의 기준을 최종 기준으로 채택하면 100·110·120·130·140·150으로 조정한다. 이 차이를 확인하지 않고 되돌리지 않는다.
- 다음 레벨 필요 경험치 `(n-1)×100`, 레벨업당 스탯 포인트 1개, 서버 중복 보상 방지는 유지한다.
- 크리티컬 적용 전후의 평균 클리어 시간과 초반 레벨업 속도를 함께 측정해 최종 성장 속도를 판단한다.

## 4. 이아이 최종전

### 회의 결론

기존 ‘말 부수기 + 학과별 공격 + 쓰러짐 뒤 수호알의 구출’ 형식을 유지한다. 전투 전체를 학과 미니게임 리믹스로 교체하는 안은 후속 확장 아이디어로 남긴다. 우선 시간 단축, 스토리 전달, 구출 연출, 학과 구분을 강화한다.

### 전투 흐름과 시간

- 목표 제안: 조작하는 전투 구간을 **90~110초**로 단축한다. 클릭 대화와 소원 입력 시간은 따로 측정한다.
- 초반에는 말 부수기·회피를 익힐 시간을 준다. 공격이 더 이상 의미 없는 상태에서 오래 버티는 구간을 우선 줄인다.
- 학과별로 ‘공격 변화 → 검은 기운 과부하 → 쓰러짐 → 수호알 구출 → 다음 구간’이 짧고 명확하게 이어지도록 한다.
- 난이도 자체를 무조건 올리거나 플레이어 체력을 줄여 시간을 단축하지 않는다. 대기 시간·구출 지연·강제 붕괴까지의 시간을 먼저 조정한다.
- 완료 기준: 테스트 참가자가 목표와 구출 이유를 설명할 수 있고, 후반에 의미 없이 시간을 보내는 구간이 없다.

### 쓰러짐을 납득시키는 스토리

- 회피 불가능한 공격 직전에 검은 기운이 압도적으로 커지는 짧은 예고와 대사를 넣는다.
- 이 쓰러짐은 실패 화면으로 처리하지 않고 ‘수호알이 지켜 주는 이야기의 전환’으로 보여준다.
- 죽어야 진행된다는 공략 설명을 앞세우기보다, 쓰러지는 순간 알이 반응하는 원인과 결과를 화면에서 연결한다.
- 보완 대사 예시: ‘검은 기운이 너무 거세…’ → 해당 수호알의 ‘아니야, …’ 위로 → 체력 회복.
- 최종 문구는 팀에서 확정한다. 기존 이야기와 상충하는 장문의 새 설정은 추가하지 않는다.

### 수호알 구출과 학과 전환

- 구출 순간 1~1.5초 정도 전투를 잠깐 정리하고, 해당 알을 캐릭터 위·주변의 겹치지 않는 위치에서 크게 보여준다.
- 픽셀 빛·작은 날개 또는 빛 조각이 알에서 플레이어로 이어지고, 하트가 다시 채워지는 과정을 보여준다.
- 위로 대사는 이아이 공격 자막과 다른 위치·색·형태로 보여준다. 해당 학과명과 알 이미지를 함께 표시한다.
- 다음 학과로 넘어갈 때 배경 가장자리와 공격 색이 해당 수호알 색으로 바뀐다. 전체 화면을 진하게 덮어 공격이 안 보이게 하지 않는다.
- 학과별 공격은 기존 사전게임에서 본 모티프를 활용하되, 동시에 쏟아지는 글씨와 작은 효과 수를 줄인다. 크기·간격·명암을 확보한다.
- 완료 기준: 설명을 듣지 않은 사람이 어느 알이 구출했는지, 체력이 회복됐는지, 다음 구간으로 넘어갔는지 바로 알아본다.

### 대사·캐릭터 표시

- 아무·이아이·플레이어 화자 색을 구분한다.
- 로그인한 플레이어 대화에는 본인 닉네임을 표시하고, 게스트에는 ‘플레이어’를 사용한다.
- 수호캐릭터·알 모임은 더 크게 보여주되 플레이어·대화창과 겹치지 않게 한다.
- 앞서 요청한 화면 하단 대화창, 한 개의 자물쇠, 피격 시에만 흔들림, 픽셀 엠브리오·축제 조명, 마지막 독백 후 메인으로 복귀는 유지한다.

## 5. 소원 게시판 운영 기능

회의의 최종 정리: **아이디당 소원 1개 / 닉네임 공개 체크 / 수정 불가 / 삭제 후 재등록 가능**.

### 사용자 기능

- 새 소원 작성은 로그인 계정에 연결한다. 기존 게스트 소원은 보존하되 새 작성의 계정 정책과 구분한다.
- ‘닉네임 공개’ 체크란을 둔다. 기본은 비공개를 제안하며, 비공개 글은 ‘익명’으로 표시한다.
- 닉네임은 서버가 계정에서 가져온다. 익명 게시물 응답에는 비공개 닉네임이나 계정 식별자를 포함하지 않는다.
- 내 소원이 이미 있으면 새 작성 대신 내 소원과 ‘삭제하기’를 보여준다.
- 수정 기능은 제공하지 않는다. 삭제 확인 후 새 소원을 등록할 수 있게 한다.
- 학과 필터·학과별 메모지 색·현재 도트 보드 UI는 유지한다.
- 아웃트로에서 로그인 필요 상태가 발생해도 이야기가 막히지 않게 한다. 입력 초안과 이후 로그인·게시 동선을 별도로 처리한다.

### 관리자 기능과 데이터 변경

- 서버에서 확인한 관리자 계정만 부적절한 소원을 삭제할 수 있게 한다. 일반 사용자에게 관리자 권한을 맡기지 않는다.
- 관리 화면에는 게시물 목록·검색·삭제와 삭제 기록을 제공한다. 본인 삭제와 관리자 삭제를 구분한다.
- 게시물에 작성자 계정, 공개 여부, 삭제 상태를 추가하고 활성 글에 대해서만 계정당 1개를 DB 제약으로 보장한다.
- 작성·삭제를 동시에 요청하거나 여러 탭에서 작성해도 제한을 우회하지 못하도록 한다.
- 기존 글은 닉네임으로 작성자를 추측하지 않는다. 기존 서버 소유 식별 정보로 확인 가능한 글만 계정과 연결한다.
- 기존 한 계정의 여러 글은 백업 후 정리 정책을 적용한다. 제안은 최신 1개만 활성으로 남기고 나머지는 기록을 보존하는 방식이다. 기존 비로그인 글은 임의 계정에 배정하지 않는다.
- 마이그레이션 전에 백업하고, 기존 글·학과 색·익명 표시·삭제 후 재작성까지 검증한다.
- 완료 기준: 본인 글만 삭제할 수 있고, 익명 글의 작성자 정보가 공개 API에 노출되지 않으며, 삭제 후 새 글 1개를 작성할 수 있다.

## 6. 추가 게임과 홍보·운영 연계

### 별도 범위로 남길 항목

- 랜덤 미니게임 2종 추가는 종류·규칙이 미정이다. 핵심 오류 수정과 최종전 정리 뒤 구현한다.
- 후보 제안: 짧은 타이밍 게임, 짧은 기억·순서 게임. 기존 가위바위보·카드·연타와 조작이 겹치지 않고 모바일에서도 가능한 것을 우선한다.
- 회의의 ‘스탯 : 퀴즈’ 메모는 구체적인 변경 결론으로 보기 어렵다. 보스 구조를 바꾸는 작업에는 바로 반영하지 않는다.
- 오프라인 QR 스캔 스탯 지급은 지급량·대상 부스·계정당 횟수가 정해진 뒤 구현한다. 단순 고정 URL 방문만으로 반복 지급되는 방식은 피한다.
- 게임 완료 인증 스티커·도장, 사후게임 랭킹 경품은 현장팀과 대상·확인 방법·기준 시간을 맞춘다. 랭킹 기준을 중간에 바꾸면 기존 기록 처리도 함께 정한다.
- 3분 인트로 웹게임, 하트 모양 보스 패턴은 제안 단계이므로 이번 필수 수정에 넣지 않는다.

## 7. 실제 작업 묶음과 팀이 맞출 사항

1. **오류 수정 묶음**: 사전게임 완료 조건, 캐릭터 중심, 보스 판정, 패턴 회피 시간, 사망 후 관전. 수정 후 팀원들이 다른 계정으로 동시 플레이한다.
2. **최종전 묶음**: 구간별 시간, 학과 색·공격 모티프, 구출 연출, 화자·닉네임. 짧은 테스트 영상을 보고 이야기 전달 여부를 확인한다.
3. **게시판 묶음**: 계정 소유·공개 여부·작성 제한·사용자 삭제·관리자 삭제·DB 마이그레이션. 데이터 백업 후 배포한다.
4. **성장 묶음**: 경험치 범위 확정, 크리티컬 적용, 평균 클리어 시간·레벨업 속도 재측정.
5. **확장·홍보 묶음**: 추가 미니게임, QR 보상, 현장 인증 및 카드뉴스에 필요한 최종 자료.

팀에서 맞출 것은 경험치 100~200 유지 여부, 크리티컬 수치, 최종전 대사·공격 모티프, 관리자 계정과 기존 글 정리 정책, 오프라인 보상 규칙이다. 회의에서 이미 정한 기존 형식 유지·게시판 수정 금지 등은 다시 논의하지 않고 작업 기준으로 삼는다.

모든 묶음은 해당 기능 테스트, 전체 회귀 검사, 모바일 화면 확인을 마친 후 배포한다. 서버 관련 묶음은 서로 다른 계정으로 같은 방에서 확인하며, 데이터 변경이 있는 게시판 묶음만 마이그레이션을 수행한다.
