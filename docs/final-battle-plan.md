# 최종전 기획안 — 마음의 말 깨부수기

> 구현 상태: `MVP` · 운영 registry에 `published`
>
> 진입 조건: 서로 다른 사전게임 5종 `ALL CLEAR`
>
> 계정 스탯: 사용하지 않음(`usesAccountStats: false`)

## 1. 한 줄 기획

화면 위에서 내려오는 부정적인 문장의 핵심 표현을 자동 발사 탄으로 깨뜨리고, 다섯 수호알과 함께 그 말을 회복의 문장으로 바꾸는 세로형 최종전이다.

목표는 이아이를 공격하거나 벌주는 것이 아니다. 마음을 가두는 말을 안전한 속도로 흘려보내고, 다시 시도할 수 있는 말로 바꾸는 경험을 만든다. 특정 상용 게임의 화면·캐릭터·사운드·수치를 복제하지 않는다.

## 2. 현재 MVP 흐름

```text
사전게임 5종 CLEAR 확인
→ DS 라운드 14초
→ DS 수호알 회복·수집
→ CS 라운드 14초
→ CS 수호알 회복·수집
→ CSE 라운드 14초
→ CSE 수호알 회복·수집
→ AI 라운드 14초
→ AI 수호알 회복·수집
→ AIDS 라운드 14초
→ AIDS 수호알 회복·수집
→ 다섯 수호알이 마지막 문장을 4초 동안 정화
→ CLEAR
```

- 논리 전투 영역은 `450 × 800`이다.
- 각 라운드는 정화한 문장 수와 관계없이 `roundDurationMs`가 지나면 끝난다.
- 라운드 끝의 `collapse`는 피할 수 없는 부정적인 말이 플레이어에게 닿아 마음이 잠시 멈추는 순간이다. 패배나 죽음은 아니며 곧 수호알이 나타난다.
- `collapse` 시 남아 있는 일반 문장과 탄은 제거되고, 화면 폭 전체의 강제 문장이 플레이어 위치에 충돌한 뒤 `RECOVERING` 상태로 넘어간다. 이 장면은 `forcedHitCount`에 라운드당 정확히 한 번 기록된다.
- 강제 충돌 연출은 최소 `520ms` 동안 유지되어, 수호알과 위치가 우연히 겹쳐도 맞는 장면이 생략되지 않는다.
- 수호알은 즉시 접촉해 얻거나, `1200ms` 뒤 플레이어에게 다가오는 자석 이동으로 얻는다.
- 다섯 번째 수호알을 얻으면 마지막 문장과 수호알 다섯 개가 나타난다. 마지막 문장은 `4000ms` 동안 자동으로 정화된 뒤 `CLEAR`가 된다.

## 3. 전투와 판정

플레이어는 하단에서 이동하고 기본 탄은 `180ms`마다 자동 발사된다. 일반 문장은 위에서 아래로 이동하며 강조된 핵심 표현만 피격 대상이다.

```text
기본 탄 피해 = 20
일반 핵심 HP = 60
일반 핵심 정화에 필요한 적중 = ceil(60 / 20) = 3회
```

- 핵심 HP가 0이 되면 원문이 회복 문장으로 바뀌어 잠시 표시된 뒤 사라진다.
- 문장이 화면 아래로 벗어나면 점수나 생존 페널티 없이 제거된다.
- 문장이 플레이어와 닿으면 `hitCount`가 1 증가하고 콤보가 0으로 돌아가며, 해당 문장은 제거된다.
- 충돌 뒤 `700ms` 동안 같은 종류의 중복 피격을 막는다.
- 플레이어 HP, 죽음, 생명 수, 게임 오버, 피할 수 없는 `FAIL`은 없다.
- 라운드를 버티기만 해도 다음 수호알로 진행할 수 있으므로 읽기·회복 메시지 체험이 중단되지 않는다.

## 4. 조작

| 환경 | 이동 | 발사 | 일시정지 |
| --- | --- | --- | --- |
| PC | 방향키 또는 `WASD` | 자동 | `Escape` 또는 `P` |
| 모바일 | 화면 가상 조이스틱 | 자동 | 공용 일시정지 버튼 |

- 자동 발사로 이동과 문장 읽기에 집중한다.
- 키보드와 가상 조이스틱 입력은 같은 이동 상태를 갱신한다.
- 브라우저 focus가 빠지거나 공용 pause가 열리면 시간·생성·이동을 함께 멈춘다.
- `prefers-reduced-motion` 환경에서는 장식 이동과 강조 애니메이션을 줄인다.

## 5. 다섯 수호알 — 수동 스킬이 아닌 패시브 동행

수호알은 선택하거나 버튼으로 발동하는 액티브 스킬이 아니다. 각 라운드가 끝나면 자동으로 등장하고, 접촉 또는 자석 이동으로 수집되어 플레이어 곁에 남는다. 현재 MVP에서 전투 수치를 강화하지 않으며 수집 점수, 진행 표시, 마지막 문장의 자동 정화를 담당한다.

| 순서 | 코드 | 색상 | 역할 |
| --- | --- | --- | --- |
| 1 | `DS` | `#d82f76` | 첫 라운드 완료 표시와 데이터 수호알 수집 |
| 2 | `CS` | `#363367` | 두 번째 라운드 완료 표시와 보안 수호알 수집 |
| 3 | `CSE` | `#e333bb` | 세 번째 라운드 완료 표시와 컴퓨터공학 수호알 수집 |
| 4 | `AI` | `#2ab5e4` | 네 번째 라운드 완료 표시와 인공지능 수호알 수집 |
| 5 | `AIDS` | `#fac804` | 다섯 번째 라운드 완료 표시와 AI·데이터 수호알 수집 |

각 라운드는 별도의 `collapseMessage`와 `recoveryMessage`를 가진다. 수호알별 공격력·보호막·관통·조준 보정처럼 난이도를 바꾸는 효과는 플레이테스트와 접근성 검증 전까지 추가하지 않는다.

## 6. 콘텐츠 안전 기준

- 자해·극단적 선택·혐오·외모 비하·특정 개인이나 집단을 공격하는 표현은 사용하지 않는다.
- 부정 문장은 일반적인 학습 불안, 실수, 비교, 도움 요청, 휴식에 관한 표현으로 제한한다.
- 부정 문장을 오래 강조하지 않고 핵심을 깨면 같은 위치에서 회복 문장을 보여준다.
- 회복 문장은 무조건적인 낙관을 강요하지 않고, 실수·도움 요청·휴식·재도전을 인정한다.
- JSON에는 라운드 문장 30개와 마지막 문장 1개가 있으며, 모든 `target`은 대응하는 `negative`에 정확히 한 번만 들어간다.
- 문장 ID는 중복될 수 없고 행사 전 콘텐츠 담당자가 전체 문구를 다시 검수한다.

## 7. 데이터와 초기 수치

SSOT는 `data/battle/word-breaker.json`이다.

| 항목 | 현재 값 |
| --- | ---: |
| 논리 영역 | `450 × 800` |
| 플레이어 크기·속도 | `34 × 46`, `220px/s` |
| 플레이어 시작점 | `(208, 700)` |
| 탄 속도·간격·피해 | `520px/s`, `180ms`, `20` |
| 문장 속도·생성 간격 | `58px/s`, `1600ms` |
| 일반 핵심 HP | `60` |
| 라운드 시간 | `14000ms` |
| 강제 충돌 최소 연출 | `520ms` |
| 수호알 자석 대기 | `1200ms` |
| 마지막 정화 | `4000ms` |
| 마지막 문장 정화 단계 | 수호알 5개에 대응하는 `5` |

계정의 공격·HP·방어 스탯은 이 전투에 적용하지 않는다. 모든 게스트와 로그인 사용자가 같은 수치로 플레이한다.

## 8. 점수와 완료 결과

- 핵심 문장 정화, 콤보, 수호알 수집, 마지막 정화에만 점수를 더한다.
- 문장을 놓쳤을 때 누적 점수를 빼지 않는다.
- 충돌 시 누적 점수는 유지하고 현재 콤보만 초기화한다.
- 마지막 정화가 끝나면 기존 Battle lifecycle의 `onComplete(attemptId, candidate)`를 정확히 한 번 호출한다.
- module candidate에는 `status`, `score`, `failureReason`, `metrics`, `reward`만 둔다.
- 정상 완주 결과는 `status: "CLEAR"`, `failureReason: null`, `reward: null`이다.
- `sessionId`, `battleId`, 실제 플레이 시간은 공용 Battle host가 붙인다.
- D1 랭킹이나 계정 보상은 서버 권위 검증과 반복 파밍 정책이 정해질 때까지 연결하지 않는다.

## 9. 코드 경계와 등록

```text
data/battle/word-breaker.json
css/word-breaker.css
js/battle/postgame/bosses/word-breaker/
  index.js       정적 loader 공개 API
  config.js      JSON 정규화·fail-fast 검증
  encounter.js   고정 step 판정과 라운드 상태
  collision.js   논리 좌표 충돌과 빠른 탄의 swept 판정
  patterns.js    문장·탄·수호알 생성과 이동
  battle.js      lifecycle·입력·RAF·정리
  view.js        DOM 렌더링
```

통합 지점:

1. `data/battles.json`: `published`, `usesAccountStats: false`, 사전게임 5종 `ALL_MINIGAMES_CLEAR`
2. `data/asset-manifest.json`: `word-breaker-config`, group `word-breaker`, source `CONTENT-BATTLE-005`
3. `js/battle/registry.js`: 정적 `word-breaker` loader
4. `index.html`: `./css/word-breaker.css`
5. build·validate·smoke 필수 경로와 contract test

## 10. 테스트 기준

### 데이터·계약

- 정확히 5개 라운드와 `DS → CS → CSE → AI → AIDS` 순서
- 승인 색상, collapse/recovery 문구, 고유 ID 검증
- 라운드 문장 25개 이상과 `target` 정확히 1회 포함 검증
- `roundDurationMs`가 `12000..15000` 범위인지 검증
- static loader와 config asset·group·sourceRef가 모두 연결되는지 검증

### 전투 코어

- 같은 seed와 입력에서 같은 문장 순서·위치·점수
- pause 동안 시간·위치·생성·무적 시간이 변하지 않음
- 화면 아래로 벗어난 문장이 실패나 페널티를 만들지 않음
- 충돌이 HP를 만들지 않고 hitCount·콤보·무적 시간만 바꿈
- 각 라운드 종료 뒤 수호알이 등장하고 `1200ms` 뒤 자석 이동을 시작함
- 다섯 알을 모으면 마지막 정화 뒤 `CLEAR`가 정확히 한 번 발생함
- restart·destroy가 RAF, listener, DOM을 모두 정리함

### 화면·기기

- 320px 폭 모바일, 짧은 가로 화면, 일반 PC에서 전투 영역과 조작이 잘리지 않음
- 긴 한글 문장이 읽히며 핵심 표현이 색상 외의 방법으로도 구분됨
- 조이스틱 조작 중 손가락이 플레이어와 문장을 과도하게 가리지 않음
- reduced-motion과 음소거 설정을 존중함

## 11. MVP 이후 결정할 항목

- 이아이와 다섯 수호알의 최종 자체 제작 이미지·효과음
- 문장별 속도·HP와 라운드 생성 간격의 행사 플레이테스트 값
- 수호알에 전투 패시브를 추가할지 여부와 접근성 영향
- 화면 점수를 계정 기록이나 랭킹에 연결할지 여부
- 마지막 회복 문구와 연출의 콘텐츠 담당 최종 승인

현재 MVP는 위 결정과 무관하게 죽음 없이 끝까지 완주하고 마지막 문장을 회복시키는 구조로 동작한다.
