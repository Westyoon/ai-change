# 최종전 기획안 — 마음의 말 깨부수기

> 상태: 기획 확정 전 MVP 제안서
>
> 진입 조건: 서로 다른 사전게임 5종 CLEAR
>
> 구현 원칙: 기존 Battle lifecycle과 결과 계약을 재사용하고, 특정 상용 게임의 이름·화면·캐릭터·사운드·수치를 복제하지 않는다.

## 1. 한 줄 기획

화면 위쪽의 이아이가 내보내는 부정적인 문장이 탄막처럼 내려오면, 플레이어가 다섯 수호알의 힘으로 문장의 핵심 단어를 깨뜨리고 마음을 회복시키는 세로형 스크롤 슈팅 최종전이다.

이 게임의 목표는 이아이를 공격하거나 벌주는 것이 아니다. 이아이가 스스로를 가두는 말을 깨고 다시 말할 수 있도록 돕는 것이 핵심 판타지다.

## 2. 플레이 흐름

```text
수호알 5개 확인
→ 5초 조작 안내
→ 1단계 속삭임
→ 2단계 소용돌이
→ 3단계 X알 코어
→ 마음 회복 연출
→ CLEAR / FAIL 결과
```

- 논리 화면은 세로 `450 × 800`을 우선한다.
- 넓은 PC 화면에서는 논리 화면을 늘리지 않고 좌우 장식 영역을 둔다.
- 플레이어는 하단에서 이동하며 기본 탄을 자동 발사한다.
- 부정 문장은 위에서 아래로 이동하며, 문장 안의 강조된 핵심 단어가 실제 피격 대상이다.
- 핵심 단어를 파괴하면 문장이 짧은 회복 문장으로 바뀐 뒤 빛 조각이 되어 사라진다.
- 문장 또는 검은 파편이 플레이어와 충돌하면 HP와 콤보가 감소한다.
- 수호 게이지가 가득 차면 `수호 버스트`로 화면의 위험 문장을 정화하고 보스 코어에 피해를 준다.

## 3. 조작

| 환경 | 이동 | 수호 버스트 | 일시정지 |
| --- | --- | --- | --- |
| PC | 방향키 또는 WASD | Space 또는 Enter | Escape |
| 모바일 | 플레이 영역에서 손가락 드래그 | 화면 하단의 큰 버튼 | 상단 일시정지 버튼 |

- 자동 발사를 사용해 이동과 문장 읽기에 집중시킨다.
- 모바일 드래그는 손가락 바로 아래가 아니라 약간 위에 플레이어가 위치하도록 해 가림을 줄인다.
- 키보드와 터치가 동일한 action 계약을 사용하도록 공용 `InputManager`에 연결한다.

## 4. 전투 단계

### 4.1 1단계 — 속삭임

- 목표 시간: 30초
- 한 번에 1~2개 문장이 직선 또는 느린 곡선으로 내려온다.
- 핵심 단어는 한 개이며 항상 분홍색 테두리로 표시한다.
- 수호알의 기본 효과를 하나씩 짧게 보여주는 학습 구간이다.
- 플레이어가 처음 피격되면 1회에 한해 1초 보호막과 이동 안내를 다시 표시한다.

예시 문장과 정화 문장:

| 내려오는 문장 | 파괴할 핵심 | 정화 후 문장 |
| --- | --- | --- |
| 난 분명 또 틀릴 거야 | 틀릴 거야 | 틀려도 다시 배울 수 있어 |
| 시작해도 소용없어 | 소용없어 | 작은 시작도 변화를 만든다 |
| 아무도 내 편이 아니야 | 아무도 | 도움을 청할 사람이 있을 수 있어 |
| 나는 잘하는 게 없어 | 없어 | 아직 찾고 배우는 중이야 |

### 4.2 2단계 — 소용돌이

- 목표 시간: 45초
- 한 번에 2~4개 문장과 검은 파편이 등장한다.
- 일부 문장은 핵심 단어가 두 개이며 첫 단어를 깨면 남은 단어가 이동 방향을 바꾼다.
- 화면 가장자리에서 안쪽으로 휘는 패턴과 교차 패턴을 사용한다.
- 정화한 문장을 연속으로 5개 처리하면 수호 게이지 보너스가 붙는다.
- 피해를 입어도 해당 문장을 즉시 삭제하지 않아, 같은 패턴을 보고 다시 대응할 수 있게 한다.

### 4.3 3단계 — X알 코어

- 보스 코어가 화면 상단 중앙에 나타난다.
- 코어는 보호막이 있는 동안 부정 문장을 6초마다 한 묶음씩 만든다.
- 문장 묶음을 모두 정화하면 보호막이 4초간 열리고 기본 탄과 수호 버스트가 코어에 피해를 준다.
- 코어 HP가 50% 이하가 되면 생성 간격이 6초에서 4.5초로 줄지만, 화면의 동시 문장은 최대 5개로 제한한다.
- 코어 HP가 0이 되면 공격을 즉시 정지하고 마음 회복 연출로 전환한다.

### 4.4 마무리 — 마음 회복

- 남은 탄과 타이머를 정지한다.
- 깨진 문장 조각이 다섯 수호알 색의 빛으로 바뀌어 이아이에게 돌아간다.
- 선택이나 추가 전투 없이 8~12초 안에 마무리한다.
- 스토리 원고는 현재 보류 상태이므로 MVP에서는 짧은 자체 문구만 사용한다.

## 5. 다섯 수호알의 역할

수호알은 별도 캐릭터 선택 화면을 만들지 않고 플레이어 주변의 작은 픽셀 오브젝트로 표시한다. 다섯 개를 전부 모아야 최종전에 들어올 수 있으므로 모든 효과가 함께 적용된다.

| 사전게임 ID | 전투 역할 | MVP 효과 |
| --- | --- | --- |
| `data-number-baseball` | 약점 분석 | 핵심 단어의 첫 피격 피해 `+20%` |
| `cyber-click-to-purify` | 오염 정화 | 12초마다 1회 충돌을 막는 보호막 생성 |
| `computer-code-heart` | 발사 안정화 | 기본 탄이 문장 핵심을 1회 관통 |
| `ai-ball-classification` | 표적 분류 | 가까운 핵심 단어 방향으로 최대 8도 조준 보정 |
| `ai-data-egg-sort` | 흐름 예측 | 새 문장의 진입 위치를 600ms 먼저 점선으로 예고 |

다섯 효과는 플레이 감각을 돕는 보조 기능이며 자동 클리어를 만들면 안 된다. 계정 스탯이 없는 게스트도 동일하게 완주 가능해야 한다.

## 6. 권장 초기 수치와 공식

아래 값은 첫 플레이테스트용이며 운영 확정값이 아니다.

```text
플레이어 기본 HP = 100
기본 탄 피해 = 12
기본 발사 간격 = 180ms
피격 후 무적 시간 = 900ms
수호 게이지 최대값 = 100
일반 핵심 정화 게이지 = 12
강화 핵심 정화 게이지 = 20
수호 버스트 코어 피해 = 120
보스 코어 기본 HP = 1,200
전체 제한 시간 = 150초
```

계정 전투 스탯을 사용하는 경우 기존 `createBattlePlayer()`가 변환한 `A/H/D`를 한 번만 사용한다.

```text
공격 보너스 BA = max(0, A - 1)
체력 보너스 BH = max(0, H - 1)
방어 보너스 BD = max(0, D - 1)

기본 탄 피해 = 12 × (1 + BA × 0.04)
최대 HP = 100 + BH × 8
실제 피격 피해 = max(1, 원본 피해 - BD × 0.8)
```

문장 핵심 HP는 글자 수와 단계로 계산하되 너무 긴 문장이 과도하게 단단해지지 않게 제한한다.

```text
문장 길이 L = clamp(핵심 단어의 한글 음절 수, 2, 10)
단계 배율 P = 1단계 1.0 / 2단계 1.35 / 3단계 1.7
핵심 HP = round((30 + L × 4) × P)
```

원본 충돌 피해 권장값:

- 일반 문장: 18
- 강화 문장: 26
- 검은 파편: 12
- 보스 코어 직접 충돌: 즉시 실패가 아니라 35

## 7. 점수

```text
문장 점수 = (100 + 핵심 글자 수 × 15) × 콤보 배율
콤보 배율 = min(3.0, 1.0 + 연속 정화 수 × 0.1)
단계 완료 보너스 = 단계당 1,000
남은 시간 보너스 = 남은 초 × 20
노 피격 보너스 = 1,500
```

- 피격 시 연속 정화 수만 0으로 되돌리고 누적 점수는 빼앗지 않는다.
- MVP의 결과는 기존 Battle과 같이 화면에만 표시하며 `reward: null`을 유지한다.
- D1 랭킹이나 스탯 보상은 서버 권위 검증과 반복 파밍 정책이 정해진 뒤 별도 작업으로 추가한다.

## 8. 문장 콘텐츠 안전 기준

- 자해·극단적 선택·혐오·외모 비하처럼 참가자에게 직접적인 위해가 될 수 있는 표현은 사용하지 않는다.
- 특정 개인이나 집단을 지목하는 문장을 사용하지 않는다.
- 부정 문장을 오래 강조하지 않고 파괴 직후 회복 문장을 같은 위치에 1초 이상 보여준다.
- “긍정적으로 생각하면 다 해결된다”는 메시지를 피하고, 실수·도움 요청·휴식·재도전을 인정하는 문장으로 바꾼다.
- 문장 목록은 코드에 직접 쓰지 않고 JSON에 두며 행사 전 콘텐츠 담당자가 별도 검수한다.
- 빠른 섬광, 심한 화면 흔들림, 붉은 전면 플래시는 사용하지 않는다.

## 9. 접근성과 보조 기능

- 핵심 단어는 색상뿐 아니라 두꺼운 테두리와 밑줄로 구분한다.
- 기본 글자 크기는 논리 화면 기준 22px 이상으로 하고 한 문장은 두 줄을 넘지 않는다.
- `prefers-reduced-motion`에서는 곡선 이동, 흔들림, 파편 회전을 줄이고 직선 이동으로 바꾼다.
- 피격·버스트에는 시각 효과와 함께 짧은 비언어 SFX를 제공하되 음소거 상태를 존중한다.
- 화면 읽기 안내는 모든 탄 위치를 읽지 않고 단계 변경, HP 25% 이하, 버스트 준비만 제한적으로 알린다.
- 키보드 focus와 모바일 버튼 최소 터치 영역 44px을 보장한다.
- 일시정지 중에는 전투 시간, 생성 타이머, 투사체가 모두 멈춰야 한다.

## 10. 데이터 구조 제안

새 파일은 `data/battle/word-breaker.json`으로 둔다.

```json
{
  "schemaVersion": 1,
  "implementationStatus": "MVP",
  "arena": { "width": 450, "height": 800 },
  "timeLimitSec": 150,
  "player": {
    "baseHp": 100,
    "baseDamage": 12,
    "fireIntervalMs": 180,
    "invulnerableMs": 900
  },
  "boss": { "maxHp": 1200, "shieldOpenMs": 4000 },
  "guardianBurst": { "maxGauge": 100, "coreDamage": 120 },
  "phases": [],
  "phrases": [
    {
      "id": "fear-001",
      "negative": "난 분명 또 틀릴 거야",
      "target": "틀릴 거야",
      "reframe": "틀려도 다시 배울 수 있어",
      "tier": 1
    }
  ]
}
```

필수 검증:

- `id` 중복 금지
- `target`이 `negative` 안에 정확히 한 번 존재
- 문장과 핵심 단어 길이 제한
- 허용된 `tier`만 사용
- 수치가 유한한 양수인지 확인
- 최소 문장 수와 단계별 분포 확인

## 11. 코드 경계

```text
js/battle/postgame/bosses/word-breaker/
  index.js       정적 loader 공개 API
  config.js      JSON 정규화와 검증
  encounter.js   단계, HP, 생성, 결과 상태
  patterns.js    문장 이동 경로와 생성 순서
  collision.js   탄·핵심·플레이어 충돌 판정
  view.js        DOM 또는 canvas 렌더링
  battle.js      lifecycle과 입력·정리 연결
```

통합 시 필요한 변경:

1. `data/battles.json`에 `word-breaker` 정의와 기존 5종 CLEAR 조건 추가
2. `data/asset-manifest.json`에 config와 승인된 자체 제작 asset 등록
3. `js/battle/registry.js`의 정적 allowlist에 loader 추가
4. `css/word-breaker.css`를 추가하고 `index.html`에서 로드
5. `scripts/validate.mjs`와 build 필수 파일 목록 갱신

모듈은 기존 계약을 그대로 따른다.

```text
init(config, { signal })
→ start({ attemptId })
→ pause(reason) / resume()
→ onComplete(attemptId, candidate)  // attempt당 정확히 한 번
→ restart({ attemptId }) / destroy()
```

개별 모듈은 `CLEAR` 또는 `FAIL`, 점수, 실패 사유, 지표만 반환한다. `sessionId`, `battleId`, 실제 플레이 시간, 보상 정책은 공용 Battle host가 소유한다.

## 12. 테스트 기준

### 단위 테스트

- 같은 seed에서 같은 문장 순서와 이동 패턴 생성
- 핵심 단어만 피해를 받고 장식 글자에는 피해가 없음
- 관통 횟수, 조준 보정 각도, 보호막 주기가 상한을 넘지 않음
- 피격 무적 시간 중 중복 피해 없음
- 수호 게이지 100에서만 한 번 발동하고 0으로 복귀
- 보스 보호막이 닫힌 동안 코어 피해 없음
- pause 동안 시간·위치·생성 수가 변하지 않음
- attempt마다 `onComplete`가 정확히 한 번 호출
- restart와 destroy가 RAF, timer, listener, DOM을 모두 정리

### 화면·기기 테스트

- 320px 폭 모바일, 짧은 가로 화면, 일반 PC에서 전투 영역이 잘리지 않음
- 드래그 중 손가락이 플레이어와 핵심 문장을 과도하게 가리지 않음
- 긴 한글 문장이 두 줄 안에서 읽히고 서로 겹치지 않음
- reduced-motion과 음소거 설정이 즉시 반영
- 키보드만으로 시작·이동·버스트·일시정지·재도전 가능

### 통과 목표

- 초견 CLEAR율 35~55%
- 규칙을 아는 참가자의 두 번째 도전 CLEAR율 60~75%
- 평균 플레이 시간 90~130초
- 피격 원인을 이해하지 못한 응답 10% 미만
- 모바일과 PC의 CLEAR율 차이 15%p 이내

## 13. MVP와 후속 범위

MVP에 포함:

- 3단계 세로 슈팅
- 검수된 부정/회복 문장 24개 이상
- 다섯 수호알의 자동 보조 효과
- 수호 버스트
- PC·모바일 입력, 일시정지, 재도전, 결과 화면
- 기존 Battle 잠금과 lifecycle 연결

MVP에서 제외:

- 음성 연기와 상용 BGM
- 멀티플레이
- 서버 랭킹·보상 지급
- 캐릭터·수호알 선택 또는 강화 트리
- 긴 컷신과 현재 보류 중인 전체 스토리 원고
- 타사 게임의 UI, 캐릭터, 적 패턴, 사운드 복제

## 14. 구현 전 결정할 항목

- 최종 게임 표시 이름
