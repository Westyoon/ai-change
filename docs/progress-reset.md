# 진행 초기화와 화면 복원

설정의 진행 초기화는 로그인한 계정의 스토리·학과 미니게임 완료 기록과 현재 브라우저 진행을 함께 지운다. 음량 설정, 계정 스탯·레벨·사후게임 성과·랭킹·산책 보상 이력은 유지한다. 성공하면 기본 메인 화면으로 돌아가고 Story는 인트로부터 시작한다. 저장된 캠퍼스 위치도 지워 첫 시작 위치를 사용한다. 계정 초기화가 실패하면 브라우저 진행을 먼저 지우지 않는다.

기존 구현은 브라우저 SaveManager만 초기화해 계정 완료 기록이 계속 합쳐졌고, 메인 화면의 축제 장식은 켜는 처리만 있었다. `POST /api/progress/reset`은 로그인·동일 Origin·빈 요청 본문을 확인한 뒤 해당 계정의 `story_progress`, `game_results`를 한 D1 batch로 삭제한다. 다른 계정과 획득 보상 테이블은 수정하지 않는다. 이 변경에는 DB migration이 필요하지 않다.

AccountService는 진행 업로드가 끝난 후 초기화를 처리하고, 초기화 중 요청된 이전 진행 가져오기는 생략한다. 초기화 이전/도중의 세션 응답이 뒤늦게 완료 기록을 되살리지 못하도록 세대를 갱신한다. SaveManager는 변경 구독을 제공하고, 메인 메뉴와 학생 색상은 로컬 변경과 계정 변경을 함께 관찰한다. 축제 배경·조명·이아이·합성 음악도 다시 끌 수 있다.

검증: 실제 Worker+SQLite 계약 검사로 계정 격리, 재시도, 보상 유지, 인증·Origin·메서드 검사를 확인했다. 계정 서비스에서는 진행 업로드와 초기화 경합, 뒤늦은 세션 응답을 검사했다. 브라우저에서 로그인/비로그인 × PC 1280px/터치 모바일 390px의 설정 초기화 → 기본 메인 → 새로고침 → 인트로 → 어두운 학생 5명 흐름, 음량·위치 초기화, 서버 실패 시 보존, 이미 열린 메뉴의 장식 해제를 확인했다. 테스트 528개, HTTP 80개+93개, 빌드, TypeScript 검사가 통과했다.
