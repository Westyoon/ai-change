# 캠퍼스 이동 시제품

브랜치: `feature/campus-follow-camera`

기존 작업의 복귀 기준: `feature/gameplay-polish-integration` / `cc2fd09`.
해당 기준 커밋은 원격에 푸시했다. 운영 배포는 변경하지 않았다.

## 구현된 구조

- 사전·사후 공통 캠퍼스 장면. 사전은 보라색, 사후는 계정 머리색·닉네임을 사용한다.
- 원본 1672×941 배치에 맞춘 길·장애물 데이터. 4px 이동 마스크로 변환하며 발밑 12×8 영역 전체를 검사한다.
- 연속 이동과 벽 미끄러짐. 프레임 지연·대각선 이동으로 벽을 관통하지 않게 한다.
- 캐릭터 추적 카메라. PC·모바일 모두 맵 일부만 표시하고 맵 경계에서 멈춘다.
- 월드 좌표와 카메라 좌표 분리. 화면 회전 때 캐릭터 위치는 바뀌지 않는다.
- 학과 NPC와 최종전 입구를 기존 이야기·게임 경로에 연결한다.
- 사후 보스 입구는 기존 서버 방 로비를 사용하고, 필드 X알은 기존 랜덤게임을 연다.
- 사후 위치는 별도 `campus-outdoor-v1` 구역으로 동기화해 기존 맵 좌표와 섞이지 않게 한다.
- 사전·사후 위치를 별도로 보관하고, 맵 버전이 바뀌거나 저장 위치가 길 밖이면 안전 시작점으로 복구한다.
- ECC·학생문화관 고유 맵 ID는 준비했으나 실내 아트와 실내 이동 데이터는 아직 연결하지 않았다.

## 원본 에셋 연결

이미지젠으로 만든 대체 시안은 사용하지 않는다. 사용자가 직접 만든 원본의 건물·배치를 보존한다.

다운로드 폴더의 `게임맵.png`(1672×941)를 변형 없이 `assets/maps/campus.png`로 복사했다.
`data/app-config.json`의 `features.campusMap`을 true로 바꿔 실험 브랜치에서 새 맵을 활성화했다.
운영 사이트에는 배포하지 않았다.

길 데이터는 원본 이미지를 보고 작성한 초안이다. 실제 원본을 연결한 뒤 좁은 통로, 나무 가장자리, 벤치·가로등 등의 세부 판정을 시각적으로 확인해야 한다.
`?campusDebug=1`로 열면 이동 가능 마스크를 겹쳐 볼 수 있다.

## 검증

`node --test tests/unit/campus-map.test.mjs`

- PC·모바일 크기의 카메라 중심·경계·좌표 변환
- 발밑 전체 영역 충돌, 얇은 장애물 관통 방지, 벽 미끄러짐
- 시작점에서 모든 NPC·게임 입구까지 발밑 박스를 유지한 연결성 검사
- 건물·정원 차단, 오래된 위치 데이터 복구, 준비되지 않은 실내맵 진입 방지

전체 테스트와 서버 타입 검사도 실행한다. 원본 연결 전에는 실제 화면·원본과 충돌 경계의 일치를 검증 완료했다고 말하지 않는다.

## 취소·비교

- 새 맵을 끄기만 하려면 `features.campusMap: false`를 유지한다.
- 전체 기준 상태로 돌아가려면 변경 사항이 커밋된 상태에서 `git switch feature/gameplay-polish-integration`을 실행한다.
- 새 브랜치는 병합하지 않고 비교·실험할 수 있다. 운영 사이트에는 별도 배포 전까지 반영되지 않는다.
